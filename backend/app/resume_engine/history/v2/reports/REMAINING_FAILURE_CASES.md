# Remaining failure cases and proposed rules

The supplied development labels have no remaining extraction mismatches in the final measured run. That does not mean the engine handles every resume or that every unlabelled semantic field is correct.

| Case | Current behavior / remaining risk | Proposed rule or validation |
| --- | --- | --- |
| Real legacy `.doc` | Conversion code exists, but LibreOffice was unavailable, so integration is untested. Original OLE text is not an independent reference. | Install a pinned LibreOffice build; add binary DOC fixtures and compare adjudicated text before/after conversion. |
| Low quality scans, mixed scripts, rotated text | Only one clean English scanned page (41 words) was measured. OCR can substitute, merge or miss words. OCR is flagged, and candidates are capped below the review threshold. | Add independently transcribed scans across resolutions/languages; configure Tesseract language/PSM and measure each variant. Never autocorrect from a dictionary without preserving the OCR original. |
| Mixed image and digital text on one page | OCR triggers for fewer than 20 digital words or no fonts. An image-only region on an otherwise dense digital page can be missed. | Detect image regions lacking overlapping text; OCR those regions and deduplicate by boxes while retaining both sources. |
| Overlapping columns, asymmetric floating boxes, rotated PDFs | Whitespace XY-cut assumes axis-aligned, non-overlapping blocks. No universal reading-order claim is made. | Add rotation-aware coordinates and explicit column hypotheses; verify against labelled line-order sequences. Keep ambiguous flows separately reviewable. |
| Borderless tables | Only ruled-table strategies are enabled by default. Unruled tables use XY-cut and may not acquire row identities. | Add a config-selectable text-alignment table detector and require repeated column anchors before row grouping. |
| DOCX AlternateContent, drawings, charts, SmartArt or altChunk | XML text containers are supported, not a full Word renderer. Text within imported non-Word payloads is not resolved. altChunk generates a warning. Alternate representations may contain duplicate text. | Add relationship-aware payload readers and a documented AlternateContent choice policy; keep unselected text as an alternate source. |
| DOCX section/page rendering | Headers/footer XML parts are emitted once, not expanded for physical pages. Floating boxes follow anchor order. | Use Word/LibreOffice rendering only as an additional layout reference; keep original XML provenance. |
| DOCX rendered numbering and tracked changes | Literal w:t/delText text is retained, caps recorded, automatic numbering marked as list metadata. Generated list numbers are not reconstructed. Tracked deletions are kept with a warning. | Resolve numbering.xml into separate display labels; introduce an explicit tracked-change policy and parallel original/final views. |
| PDF damaged font mappings and ligatures | CID tokens map to bullets per specification. Other mapping errors or font-split words may fail the raw multiset gate. | Use per-font mappings and character adjacency with original glyph records; never suppress mismatches to pass completeness. |
| Names without typography or far down a sidebar | Early short heading-like text is only a low-confidence fallback. It can still pick an occupation or label. | Annotate more header/first-cell layouts; rank candidates with explicit exclusion dictionaries and wider configured search, preserving alternatives. |
| International locations and phones | Locations target US city/state patterns. Phone default is US; plausible fictional/invalid values remain visible but need review. | Add region-specific location grammars and labelled Indian/international contacts; set the phone region per deployment. |
| Unknown headings and multilingual sections | Known synonyms score strongly. Unknown typographic H1s become custom at low confidence; unstyled unknown labels may remain text. | Add reviewed locale dictionaries; calibrate font/color/spacing weights on unseen templates and preserve custom labels. |
| Ambiguous skill names | Longest phrase and case/boundary rules stop tested Go/Branch/JS mistakes. The seed gazetteer has limited coverage and can still have semantic false positives. | Import a versioned ESCO/O*NET vocabulary with provenance; add context constraints for ambiguous aliases and measure ontology-level precision/recall. |
| Date-like citation pages | Dates in publication sections are excluded; a genuine employment interval inside a misclassified publication section could be missed. | Require job/education context for date normalization and retain all regex spans as separate candidates when uncertain. |
| Complex experience entries | Multi-cell rows and conventional title/company/date/bullet blocks pass supplied labels. Promotions, multiple employers per role, same-line multi-roles and atypical chronology remain unmeasured. | Add nested employer/role grouping with explicit line spans, and annotate per-bullet assignment rather than only counts. |
| Confidence calibration | Rule scores are not statistical probabilities; many fields use deterministic fixed scores. | Calibrate against an adjudicated held-out set and report reliability by field and confidence band. |
| Repeated margins | Only exact repeats are suppressed, but a genuine repeated body line in the configured page margin can be mistaken for a header/footer. | Require a consistent positional band across pages before suppression, retaining the existing raw-text audit. |

## What the measurements do not cover

Word multiset equality does not prove reading order, character-level equality, visual accessibility, or semantic understanding. Heading metrics cover H1 database boundaries; they do not score every TITLE/SUBTITLE/H2/BULLET/TEXT tag. Field metrics cover the explicit fields in each gold JSON. They do not measure university/institution extraction, certification entities, arbitrary portfolio URLs, publication metadata, all possible skills, or complete experience bullet text assignment. Those source texts remain in their sections and raw lines.

The corpus contains dummy phone numbers and repeated personas. No user-supplied gold files, held-out resumes, real DOC files, or user scans were present. A production acceptance claim needs independently adjudicated labels and untouched test data.
