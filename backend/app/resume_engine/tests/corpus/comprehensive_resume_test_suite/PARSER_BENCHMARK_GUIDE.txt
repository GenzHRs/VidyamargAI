# Comprehensive Multi-Format Resume Parser & Extraction Benchmark Suite

This archive contains a balanced variety of real-world resume formats in both DOCX and PDF formats. It is specifically designed to stress-test resume parsing algorithms, ATS engines, layout analyzers, OCR systems, and LLM text extractors against challenging structural patterns.

---

## 📁 Included Resume Formats & Files:

### 1. Two-Column Sidebar Layouts (Vertical Split)
- **`01_DOCX_Two_Column_Sidebar_Layout.docx`** (Claire Dupuis — Senior UX Designer)
- **`04_PDF_Two_Column_Sidebar_Layout.pdf`** (Lucas Moreau — Senior DevOps/SRE)
  * *Parser Test Case:* Left column contains metadata (contact, skills, certifications, education) while right column contains chronology.
  * *Common Extraction Failure Tested:* Tests whether parser reads left-to-right across columns (interleaving text like "CONTACT CLAIRE DUPUIS Email: Senior UX") or properly traverses independent columns.

### 2. Heavy Table-Grid Resumes (Explicit Table Cells)
- **`02_DOCX_Heavy_Table_Layout_Resume.docx`** (Devon Hastings — Senior Financial Analyst)

  * *Common Extraction Failure Tested:* Tests table boundary awareness, cell order preservation, and whether tabular rows get flattened cleanly into structured JSON.

## 🧪 Resume Parser Benchmark Checklist (What to Verify):

1. **Contact Information:** Check if phone numbers, emails, locations, and LinkedIn URLs are correctly extracted regardless of whether they sit in a header table, banner, or sidebar.
2. **Column De-interleaving:** Confirm that 2-column documents do NOT merge lines horizontally between column 1 and column 2.
3. **Table Cell Integrity:** Verify that table-formatted job histories (Date in col 1, Company in col 2, Bullet points in col 3) are mapped to a single unified job entry rather than disjointed fragments.
4. **Acronym & Metric Capture:** Check if figures ($22M, 99.995%, 60 FPS, 6 patents) and credentials (CPA, CKA, MBA, Ph.D.) are captured accurately.

*Note: All identities, numbers, emails, and entities in this archive are realistic dummy data created strictly for software and parser testing.*
